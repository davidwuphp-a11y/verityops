# Read-only preflight for a separately authorized sandbox

This worksheet describes an operator procedure. The local package does not connect to a customer system.

1. Obtain written authorization covering the isolated test partition, reset operation, named operator, read-only identity, allowed exports, expiry and business acceptance owner. Keep action credentials with the operator.
2. Identify the authoritative posting system, stable refund identifiers, the true refund-to-order foreign key or unique chain through the original payment, units, currency, eligibility rule version and effective event. Record the observation cutoff and convergence evidence for all three resources.
3. Have the ledger owner produce an independent witness for the agreed partition and watermark. Account for orphan and ambiguous postings before filtering. The witness must be independent of the tested view, its restrictive predicates and its pagination path.
4. With the actual scoped role, exhaust all pages using a stable order or cursor. Record page boundaries and the terminal marker. Compare stable IDs, multiplicities, ownership, amounts and statuses bidirectionally. Exercise a second refund, same-key foreign order, zero-row control and page boundary in approved synthetic data.
5. Record discrepancies, source versions, read windows and evidence references. Missing authorization means no connection. Incomplete evidence, unexplained differences or an unresolved deadline yields preflight INCONCLUSIVE. Successful preflight permits the agreed tests; it does not determine their verdicts.

The synthetic missing-row test reads two source IDs. The filtered view returns one and independently counting that same view also gives one. This is a reproducible counterexample to relying on the view's own count.
